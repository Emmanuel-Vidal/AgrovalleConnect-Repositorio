
# Sprint 2 Retrospective — AgroValle Connect

## ¿Qué salió bien?

- Se implementaron pruebas unitarias utilizando JUnit 5.
- Se utilizó Mockito para validar la lógica de negocio de manera aislada.
- Se configuró JaCoCo para medir la cobertura del proyecto.
- Se implementó integración continua mediante GitHub Actions.
- Se consolidó la arquitectura MVC y se mejoró la organización del código.
- Se logró una cobertura de pruebas del 97 %.

---

## ¿Qué pudo mejorar?

- La organización inicial de las ramas Git pudo realizarse desde etapas más tempranas.
- Algunas actividades de documentación se completaron después de terminar el desarrollo.
- La división de tareas dentro del tablero pudo ser más detallada.
- Faltó realizar revisiones periódicas del backlog durante el sprint.

---

## ¿Qué aprendimos?

- La integración continua permite detectar errores antes de integrar cambios al proyecto.
- Las pruebas automatizadas mejoran la confiabilidad del software.
- JaCoCo facilita la identificación de componentes sin cobertura de pruebas.
- El uso de ramas de desarrollo ayuda a mantener estabilidad en la rama principal.

---

## ¿Qué acciones tomaremos?

- Mantener actualizada la documentación durante cada sprint.
- Utilizar Pull Requests para integrar cambios a la rama principal.
- Crear tareas más pequeñas y mejor definidas dentro del tablero del proyecto.
- Mantener pruebas y cobertura actualizadas a medida que se desarrollen nuevas funcionalidades.

---

## Conclusión

El Sprint 2 permitió fortalecer significativamente la calidad técnica de AgroValle Connect. La implementación de pruebas automatizadas, integración continua y seguimiento de cobertura generó una base sólida para las siguientes iteraciones del proyecto y mejoró la mantenibilidad del sistema.
